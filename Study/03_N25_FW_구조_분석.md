## 1. 타이밍 구조

| 주기 | 소스 | 하는 일 | 위치 |
|------|------|---------|------|
| PWM ≈ **40 kHz** (추정) | MCPWM, PTPER=3000 @ 120MHz | 3상 상보 PWM, 데드타임 DTR=40 (≈333ns) | [pwm.c:34](../N25/AMR_MC_N25-PositionCtrl/AMR_MC_N25-PositionCtrl/pwm.c#L34) |
| ADC | PWM1/2/3 트리거 | R/S/T 전류 변환 | [adc.c](../N25/AMR_MC_N25-PositionCtrl/AMR_MC_N25-PositionCtrl/adc.c) `ADCTRG1` |
| **20 kHz** | Timer3 ISR (PR3=3000 @ 60MHz) | 엔코더 갱신 + **FOC 전류 루프** | [main.c](../N25/AMR_MC_N25-PositionCtrl/AMR_MC_N25-PositionCtrl/main.c) `Handler_TMR_3` |
| **500 Hz** | Timer3 ÷ 40 | **위치 루프** (`Handler_Control_Diff/Abs`) | [main.c:204](../N25/AMR_MC_N25-PositionCtrl/AMR_MC_N25-PositionCtrl/main.c#L204) |
| 1 kHz | Timer3 ÷ 20 | 속도 이동평균, **JAM/과전류 판정** | `ReadEncoder()` |

> 주석에는 "80kHz"로 적혀 있지만, PTPER=3000이고 데드타임 주석(8ns×40)으로 보아 PWM 클록은 120MHz다. 따라서 **실제 PWM은 40kHz 엣지 정렬로 추정**된다. 오실로스코프로 꼭 확인하자.
> FOC는 20kHz이므로 **PWM 2주기마다 듀티 1회 갱신**이다.

## 2. 제어 블록 다이어그램 (현재 구현)

```
 AMR 상위 제어기 (CAN, ~500Hz)
   │  dlc=8: [속도증분 int32 (×MUL=10), 피드포워드 전류 int16]
   ▼
 ┌──────────────────────── 500 Hz ────────────────────────────┐
 │ REF_MUL += NewInputRefDiff        ← 속도 명령을 "적분" → 위치 기준 │
 │ REF = REF_MUL / 10                                          │
 │ e   = REF − (NewPos + ABS_OFFSET)          [count, 16384/rev] │
 │ ė   = e − e_prev                           (필터 없음)        │
 │ Iq* = (Kp·e + Kd·ė + Ki·Σe)/10 + Iff       Kp=70, Kd=1000, Ki=0│
 │ Iq* = clamp(Iq*, ±limit)  limit: 5A(idle) ↔ 28A(주행), 20A/s 램프│
 └─────────────────────────────────────────────────────────────┘
   ▼ ref_current_q [mA]
 ┌──────────────────────── 20 kHz ────────────────────────────┐
 │ Ia=ADC0−RZ, Ib=ADC1−SZ, Ic=−Ia−Ib (3번째 센서 미사용)        │
 │ Clarke(진폭불변) → Park(θe from QEI 누적)                    │
 │ Vd,Vq = PI(Id*=0, Iq*)   Kp=700/1000, Ki=10/1000 per sample   │
 │ |V| ≤ 48000 원형 제한, 적분기 back-calc + clamp               │
 │ 역Park → (Vref, angle) → SVPWM 테이블 → PDC1..3 (반전 출력)    │
 └─────────────────────────────────────────────────────────────┘
```

**핵심 특징:**
1. **속도 루프가 없다.** 위치 PD 출력이 바로 Iq 명령(토크)이 된다. (P-PD-PI가 아니라 PD→PI 2단)
2. 상위에서 받은 속도를 펌웨어가 적분해 위치로 추종한다. 결과적으로 **"속도 명령 → 위치 서보"** 구조가 된다.
3. 기본 Ki_pos = 0 이므로 위치 루프는 PD 제어다. 정상상태 오차는 Kp에 의존한다.

## 3. 모듈별 상세

### 3.1 전류 루프 — `FOC_CurrentControl_Double()` ([FOC.c](../N25/AMR_MC_N25-PositionCtrl/AMR_MC_N25-PositionCtrl/FOC.c))

| 항목 | 구현 | 평가 |
|------|------|------|
| 전류 측정 | 2상(R,S) + 계산 T. ADC 완료까지 ISR에서 busy-wait | 3번째 센서(T_CUR)가 실장되어 있으므로 합계 진단에 활용 가능 |
| 오프셋 | `CurrentNulling()` — Gate ON, 듀티 0에서 1000회 평균 | 양호. 온도 드리프트 재보정은 없음 |
| 전기각 | `θe = (MAG_AXIS % 16384) × 360 / 2340.57` | 부팅 시 MU150 절대값으로 1회 초기화, 이후 **QEI 증분 누적만** 사용 (주기적 절대값 재동기화 없음) |
| sin/cos | 0.1° 룩업 테이블 (×1000 정수) | 양호 |
| PI | `V = (Kp·e + Ki·Σe)/1000` [표기 단위 mV] | |
| 전압 제한 | `|Vdq| ≤ 48000` 원형 제한 | Vbus를 측정하지 않아 **고정 48V 가정** |
| Anti-windup | `Esum += (Vsat − V)·Ki/Kp` + `|Esum| ≤ 44e6/Ki` | **스케일 오류** (아래 4.3) |
| 디커플링/BEMF FF | 없음 (`FF_VOLTAGE` 미정의) | 저속 AMR에서는 영향이 작지만 고속·급가속 시 추종 지연 |
| 지연 보상 | 없음 (측정각으로 바로 역변환) | 7극쌍 저속 운전에서는 무시 가능 |

### 3.2 SVPWM — `SPACE_VECTOR_COMMUTATION_Double()`
- 섹터(60°) 판별 → `T1, T2 = 0.866·Ts·(Vref/48000)·sin(...)` → 중앙 배치(T0/2)
- `Vref ≤ 48000`이면 T1+T2 ≤ 0.866·Ts → 선형 영역 안
- **스케일 주의**: 표준식은 `T1 = √3·Ts·|V|/Vdc·sin(60°−θ)`이다. 코드 식과 비교하면 Vref=48000이 "위상전압 피크 = Vbus/2 (48V 버스에서 24V)"에 해당한다. 즉 변수명은 mV지만 **실제 위상전압 [V] ≈ Vref/1000 × Vbus/96** 이다 [확인 필요]. 게인을 물리 단위로 해석할 때 주의하자.
- `NEW_AMP2`: 출력 반전(PDC = PWM_RES − duty) + Active-Low 극성 설정

### 3.3 위치 루프 — `ControlLoopDiff()` ([control.c](../N25/AMR_MC_N25-PositionCtrl/AMR_MC_N25-PositionCtrl/control.c))

```c
REF_MUL += pulse_temp;           // 속도 적분 (CAN 50ms 미수신 시 0)
e     = REF - (NewPos + ABS_OFFSET_ENC);
edot  = e - PREV_ERROR;          // 500Hz 원시 차분, 필터 없음
Iq*   = (e*Kp + edot*Kd + Ki*Σe)/10 + NewInputCurrent_f;
Iq*   = clamp(Iq*, ±TEMP_MAX_CUR_LIMIT);
```

| 기능 | 동작 |
|------|------|
| Idle 판정 | 명령 증분 0이 200틱(400ms) 이상 → idle. 증분 ≠ 0이 50틱(100ms) → 주행 |
| 전류 한계 램프 | idle: 28A → 5A로 5A/s 감소. 주행: 5A → 28A로 **20A/s** 증가 |
| Idle 오차 블리딩 | idle 중 Iq*가 한계 근처(±4.5A)이면 REF를 실제 위치 쪽으로 50cnt/틱 이동 → 정지 상태의 힘 싸움 완화 |
| BIG 에러 | 주행 중, 한계가 OVR×0.8 이상일 때만 `|e| > B_ERR` 이면 BIG. **B_ERR 기본값 65535 cnt = 4회전** |
| INP 에러 | 한 틱 증분이 `I_ERR + 1000` 초과 |
| D항 스케일 | Kd=1000 → 1 cnt/틱(≈1.8 rpm) 변화에 **100mA** 계단. 엔코더 양자화가 그대로 전류 노이즈가 됨 |
| 정지 명령(0xABCDEF) | `REMOVE_CURRENT_REF_MUL`만 저장하고 ACK. **`remove_current_flag`를 1로 만드는 코드가 없어 `CURRENT_REMOVE` 블록이 동작하지 않음 (dead code)** |

## 4. 구조적 문제점 목록

### 4.1 [치명] 보호 계층의 공백
- 빠른 보호(µs~ms)가 FW에 **전혀 없다.** 유일한 전류 보호가 "**27A 이상이 0.8초 지속**"이다.
- 게이트드라이버 nFAULT를 읽지 않아서 DRV8350이 OCP로 차단해도 FW는 그 사실을 모르고 명령을 계속 낸다.
- I²t(열 누적) 모델이 없다. 26A로 계속 밀면 CUR/JAM 에러가 **영원히 발생하지 않는다** (임계값 미만이므로).
- 온도 에러 경로가 끊겨 있다.

### 4.2 [치명] 속도→위치 적분 구조 + 포화 = 위치 오차 Windup
- 슬립·걸림·과부하로 바퀴가 명령을 못 따라가도 `REF_MUL`은 **계속 적분**된다.
- 오차 e가 커질수록 Iq*는 28A에 포화된 채로 머문다 → 모터·FET에 최대 전류가 **지속**된다.
- 바퀴가 다시 접지·해제되는 순간, 쌓인 오차를 해소하려고 최대 토크로 **"따라잡기"** 가속이 일어난다 → 다시 슬립 → 진동/충격.
- idle 상태에서만 오차 블리딩이 있고, **주행 중에는 추종오차 제한이 없다** (B_ERR=4회전까지 허용).

### 4.3 [중요] 전류 PI Anti-windup 스케일 오류
```c
Vq = (Kp*E + Ki*Esum)/1000;
// 포화 시 Vq를 ΔV만큼 깎았다면, 적분기는 ΔEsum = ΔV·1000/Ki 만큼 되돌려야 함
Esum_qd += (Vq - prev_Vq) * Igain_q1000 / Pgain_q1000;   // 실제: ΔV · Ki/Kp = ΔV · 0.014
```
- 올바른 계수(1000/Ki = 100) 대비 **약 7000배 약하다** → back-calculation이 사실상 동작하지 않는다.
- 실제 windup 억제는 `|Esum| ≤ 44e6/Ki` 클램프(=적분항 44000 → 전압 한계 근처)에만 의존한다. 전압 포화가 풀릴 때 **전류 오버슈트**가 생길 수 있다.

### 4.4 [중요] 전기각을 QEI 증분에만 의존
- 부팅 시 1회 절대각을 맞춘 뒤 QEI 카운트만 누적한다. 고전류 스위칭 노이즈로 A/B 펄스가 유실되거나 추가되면 **전기각이 영구적으로 틀어진다** (1°e ≈ 6.5 cnt).
- 각도 오차 δ → 같은 토크에 필요한 전류가 1/cos δ 배로 늘어나고, Id 성분이 생긴다 → 발열 증가 → 다시 포화 → **양의 피드백** 위험.
- MU150 절대각과 QEI 누적값의 차이를 주기적으로 감시하는 로직이 없다.

### 4.5 [중요] DC 버스 전압 미측정
- SVPWM이 48V 고정을 가정 → 배터리 전압이 54V↔42V로 변하면 전류 루프 이득이 ±13% 변한다.
- **회생 과전압을 감지할 수 없다.** 감속·제자리 회전 정지 시 회생 에너지가 버스로 돌아온다. 배터리/BMS가 받지 못하면(만충, 저온, BMS 차단) 버스 전압이 치솟는다 → 100V FET, DRV8350 파괴 가능.

### 4.6 [보통] D항 노이즈 / 속도 추정
- 500Hz 원시 차분 D항 → 1카운트마다 100mA 계단. 정지·저속에서 전류 채터링과 소음이 생긴다.
- 별도 속도 관측기가 없어서 속도 루프를 추가하려면 먼저 속도 추정기가 필요하다.

### 4.7 [보통] 기타
- `REMOVE_CURRENT` 기능 미동작 (flag set 코드 없음).
- INP 에러 시 `REF`만 되돌리고 `REF_MUL`은 그대로 → 다음 틱에 다시 점프.
- ISR 안에서 ADC busy-wait, CAN 송신 처리 → ISR 실행시간·지터를 측정해야 한다 (예: GPIO 토글로 측정).
- 3번째 전류센서(T) 미사용 → 상 단선·센서 고장 진단 기회를 놓치고 있다.
- Watchdog 비활성 (`FWDTEN = OFF`).
