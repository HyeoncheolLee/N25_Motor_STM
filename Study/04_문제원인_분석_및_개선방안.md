# 04. 필드 고장 원인 분석 및 개선 방안

> 증상: 적재 상태의 DD(차동구동) AMR 주행 중
> - FW 에러: **BIG Error, Current Error(CUR), JAM Error**
> - HW 고장: **게이트드라이버 소손, 출력 FET 소손, 과전류로 인한 코일 손상, 링자석 탈락**
>
> 질문: "PI(선형) 제어라서 비선형 영역(슬립, 마찰)에서 성능을 잃고 문제가 생기는 것인가? DOB/최적제어/SMC/H∞로 풀어야 하나?"

---

## 1. 결론부터

**"PI가 선형이라서"는 부분적으로만 맞다. 1차 원인일 가능성은 낮다.**

| 구분 | 판단 |
|------|------|
| 비선형성 자체 | 맞다. 휠-바닥 마찰(Stribeck, 슬립률-마찰계수 곡선), 하중 변화, 전류/전압 포화는 모두 비선형이다. |
| 그런데 실제로 무엇이 문제인가 | 가장 지배적인 비선형성은 **액추에이터 포화(전류 28A, 전압 한계)**다. 포화된 순간에는 PI든 SMC든 H∞든 **낼 수 있는 토크가 같다.** 제어기를 바꿔도 물리 한계는 넘을 수 없다. |
| 진짜 구조적 원인 | ① 포화 상태에서도 위치 오차를 **계속 쌓는(windup)** 기준 생성 구조 ② 포화 전류를 **0.8초 이상 허용**하는 느린 보호 ③ 게이트드라이버 Fault/과전압/온도 **보호 경로 단절** ④ 회생 에너지 미관리 |
| 고급 제어의 위치 | 위 문제를 고친 **뒤**, 부하 변동·슬립 대응 성능을 올리는 도구다. 특히 **DOB(외란 관측기)는 슬립 "감지"에 매우 유용**하다. SMC는 채터링이 FET 스트레스를 오히려 키울 수 있어 신중해야 한다. |

비유하면, 브레이크가 없는 차의 핸들을 좋은 것으로 바꾸는 것보다 **브레이크(보호)와 액셀 제한(포화·windup 관리)을 먼저 고치는 것**이 맞다.

## 2. 고장 메커니즘 가설 (FW 코드 근거 포함)

### 2.1 시나리오 A — 슬립/걸림 → 위치 오차 Windup → 최대 전류 지속 → 열 손상

```
적재 상태 급가속 / 저마찰 바닥 / 문턱 / 한쪽 바퀴 들림
  │
  ▼ 바퀴가 명령 속도를 못 따라감 (슬립 또는 스톨)
  │
  ▼ 상위 속도명령은 계속 적분됨:  REF_MUL += v_cmd   (control.c)
  │
  ▼ 위치오차 e 증가 → Iq* = Kp·e + ... → ±28A 포화 (Kp=7mA/cnt → 4000cnt ≈ 88° 만에 포화)
  │
  ├─▶ 슬립 중: 모터는 헛돌며 28A 유지 → 바퀴가 공회전 → 바닥 마찰 더 낮아짐(동마찰) → 더 슬립
  ├─▶ 스톨 중: 속도 0 + 28A → 한 상에 직류에 가까운 전류 집중 → 특정 FET/코일 상에 열 집중
  │
  ▼ 보호 판정
     · CUR: |Iq_avg| > 27A 가 0.8초 → 28A 포화면 0.8초 후 트립
     · JAM: 속도≈0 & > 25A 가 0.8초
     · BIG: |e| > 65535cnt (4회전) — 슬립으로 바퀴가 돌면 오차가 안 커지고, 스톨이면 결국 트립
  │
  ▼ 0.8초 × 28A 를 "에러 클리어 → 재시작 → 또 0.8초"로 반복 → 코일·FET 열 누적 (I²t 모델 없음)
     → 코일 절연 열화 / 자석 접착제 열화 → **코일 손상, 링자석 탈락**
```

**주의 포인트**: 26A로 계속 밀리는 상황(임계값 바로 아래)에서는 **어떤 에러도 발생하지 않는다.** 이때 코일은 정격을 훨씬 넘는 전류로 계속 가열될 수 있다 (정격 연속전류가 FW에 정의되어 있지 않음).

### 2.2 시나리오 B — 그립 회복 순간의 토크 충격

```
슬립/스톨 중 누적된 위치 오차 e_big
  ▼ 바퀴가 다시 그립을 얻는 순간 (또는 장애물 해제)
  ▼ PD가 e_big을 없애려고 28A 최대 토크로 가속 → 명령보다 빠르게 "따라잡기"
  ▼ 오버슈트 → 반대 방향 28A → 진동 (D항은 양자화 노이즈뿐이라 감쇠 부족)
  ▼ 기계적 충격 토크 반복 → 링자석·접착부·감속기 충격 하중
  ▼ 로봇은 갑자기 튀거나 비틀림 (DD 구조에서 좌우 바퀴가 따로 따라잡으면 방향이 틀어짐)
```
이것이 "비선형적인 움직임"으로 관찰되는 현상의 유력 후보다. **원인은 PI의 선형성이 아니라 기준 생성기의 windup**이다.

### 2.3 시나리오 C — 회생 과전압 → FET/게이트드라이버 파괴

```
적재(관성 큼) 상태에서 급감속 / 제자리 회전 정지 / 경사 하강
  ▼ 모터가 발전기로 동작 → 에너지가 DC 버스로 회생
  ▼ 배터리가 흡수 못 함 (만충, 저온, BMS 충전 차단, 커넥터 접촉 불량, 퓨즈/릴레이 개방)
  ▼ 버스 캡(전해 2개 + 세라믹 수 µF)만으로 에너지 흡수 → 전압 급상승
  ▼ FW는 Vbus를 측정하지 않아 감지 불가, 회생 토크 제한 없음
  ▼ 100V 초과 → FET 애벌런치 / DRV8350(VM·VDRAIN·SHx 절대최대 초과) 파괴
```
**게이트드라이버와 FET가 함께 소손되는 패턴**은 단순 과전류보다 **과전압·서지**에서 더 흔하다. 소손 보드의 버스 캡 상태, 소손 시점(감속 중이었는지)을 확인하자.

### 2.4 시나리오 D — 단락/고di/dt → 보호 경로 단절

```
코일 절연 손상(시나리오 A 결과) → 상간/상-접지 단락
  ▼ DRV8350 VDS OCP 동작 (임계가 적절하다면) → 게이트 OFF + nFAULT Low
  ▼ FW는 nFAULT를 읽지 않음 (RA7 미사용, Handler_Error 미호출) → 계속 PWM 명령
  ▼ 재시도(H 버전 OCP 모드에 따라) 또는 Enable 토글로 재기동 → 단락 상태로 반복 스위칭
  ▼ FET 열 파괴 → 하이/로우 동시 단락 → 게이트드라이버까지 손상
```
VDS OCP 임계가 너무 높게 설정되어 있다면 처음부터 보호가 동작하지 않는다 ([02 문서 §4](02_N25_HW_분석.md) 확인 필요).

### 2.5 시나리오 E — 전기각 드리프트 → 효율 저하 → 포화 가속

```
고전류 스위칭 노이즈 → QEI A/B 펄스 유실/추가 (자석 탈락이 시작되었다면 자기 트랙 신호도 약화)
  ▼ θe 오차 누적 (절대각 재동기화 없음)
  ▼ 같은 토크에 더 많은 전류 필요, Id ≠ 0 → 발열↑ → 포화 빈도↑ → 시나리오 A 가속
```

### 2.6 시나리오 간 연결

```
       (구조) 위치 windup ──┐
                            ├─▶ 장시간 최대전류 ─▶ 코일/자석 열화 ─▶ 단락 ─▶ (보호 단절) ─▶ FET/드라이버 소손
 (보호) 0.8s·27A·I²t 없음 ──┘                                   ▲
 (전원) Vbus 미측정 + 회생 ──────────────────────────────────────┘ 과전압 ─▶ FET/드라이버 소손
```

> 위 가설들은 **코드 근거와 일반적인 고장 패턴**에 기반한 것이다. 확정하려면 §5의 재현·로깅 시험이 필요하다.

## 3. "PI는 선형이라서 비선형에서 안 된다" — 이론적 검토

### 3.1 PI가 실제로 약한 부분
| 비선형 요소 | PI의 한계 | 적절한 대응 |
|-------------|-----------|-------------|
| 전류/전압 포화 | 적분기 windup → 오버슈트, 회복 지연 | **Anti-windup** (back-calculation, conditional integration) — 선형 제어기에도 표준으로 붙인다 |
| 쿨롱 마찰/Stribeck | 저속 stick-slip, 정지 떨림 | 마찰 피드포워드, DOB |
| 부하 관성 변화(적재) | 고정 게인 → 대역폭 변화 | 게인 스케줄링, DOB(공칭 모델로 강제), 적응제어 |
| 휠 슬립 (μ-λ 곡선) | 슬립 영역에서 플랜트 이득 급감 (부하토크 상실) | **슬립 감지 + 토크 제한(트랙션 제어)** — 제어 법칙보다 **감시 로직**의 문제 |
| 백래시 | 리밋 사이클 | 데드존 보상, 이중 엔코더 |

### 3.2 핵심 통찰
1. **산업용 서보의 99%는 PI/PID 캐스케이드 + Anti-windup + 피드포워드 + 관측기로 충분히 동작한다.** 비선형성은 대부분 "선형 제어기 주변의 비선형 보조 블록"(제한, windup 방지, 보상, 감시)으로 처리한다.
2. 슬립 상황에서 바퀴-바닥 사이가 전달할 수 있는 최대 견인력은 `μ·N`이다. **어떤 제어 법칙도 그 이상의 견인력을 만들 수 없다.** 해법은 "더 강하게 미는 것"이 아니라 "**밀지 않는 것**", 즉 토크를 슬립 한계 아래로 유지하는 것이다.
3. 현재 구조에서 문제를 키우는 것은 제어 법칙(PD/PI)이 아니라 **기준 신호 생성(속도 적분 → 위치)과 포화 관리**다.

### 3.3 고급 제어 기법별 적합성 (N25 / AMR 휠 관점)

| 기법 | 장점 | 단점/위험 | N25 적용 의견 |
|------|------|-----------|---------------|
| **DOB (외란 관측기)** | 부하토크·마찰 추정 → 피드포워드 보상. 공칭 모델로 강제해서 적재 변화에 강건. **추정 부하토크로 슬립 감지 가능** | 노이즈 → Q필터 설계 필요, 모델(J, Kt) 필요 | **강력 추천 (2단계)**. 속도 루프 안쪽에 넣는다 |
| **슬립 감지/트랙션 제어** | 직접적인 문제 해결 | 로봇 수준 정보(IMU, 다른 바퀴 속도)가 있으면 더 정확 | **강력 추천**. 모터 단: DOB 부하토크 급감 + 가속도 급증 = 슬립 |
| SMC (슬라이딩 모드) | 정합 외란에 강건, 유한시간 수렴 | **채터링 → 고주파 전류 리플 → FET·코일 발열, 소음.** 포화 문제는 동일 | 비추천 (우선순위 낮음). 쓴다면 경계층/Super-twisting |
| H∞ | 불확실성 대비 강건 안정성 보장, 주파수 성형 | 설계 복잡, 고차 제어기, MCU 구현 부담. 결국 선형 제어기라 포화는 별도 처리 | 연구/검증용. 실무 효과는 DOB + 잘 튜닝된 PI와 비슷 |
| LQR/LQG (최적) | 다변수(좌우 바퀴 결합) 설계 가능 | 모델 정확도 필요, 포화 미고려 | 로봇 수준(좌우 결합)에서 검토 가능 |
| **MPC** | **제약(전류, 전압, 슬립)을 직접 반영** | 연산량 큼 (20kHz 전류 루프는 어려움) | 상위(로봇 궤적·속도 프로파일)에서 가치 있음 |
| 적응제어/게인 스케줄 | 적재 질량 변화 대응 | 수렴·안정성 검증 필요 | 적재량을 상위에서 알면 간단한 게인 스케줄로 충분 |

## 4. 개선 로드맵 (우선순위)

### Phase 0 — 즉시 (안전, 재발 방지) 🔴

| # | 항목 | 구체 내용 |
|---|------|-----------|
| 0-1 | **게이트드라이버 nFAULT 감시** | RA7 입력 설정 → 20kHz ISR에서 확인 → 즉시 PWM OFF + ENABLE Low + FLT 래치. `MOTOR_FAULT` 핀 정의 수정 (RE13 → RA7) |
| 0-2 | **Handler_Error 복구** | `main.c:147` 주석 해제, `CheckError_TurnOff` 마스크에 FLT, TMP 추가 |
| 0-3 | **상전류 순시 과전류 (FW)** | 20kHz ISR에서 \|Ia\|,\|Ib\|,\|Ic\| > I_trip(예: 35A) **1~3샘플 연속 시 즉시 차단** (현재 0.8초 → 150µs 이하) |
| 0-4 | **I²t 열 보호** | `θ += (I² − I_cont²)·dt` 형태의 열 적분기 → 임계 근접 시 전류 한계 디레이팅, 초과 시 정지. I_cont는 모터 연속정격 |
| 0-5 | **3상 합 진단** | `|Ia+Ib+Ic| > 임계` → 센서/상 단선/지락 에러 |
| 0-6 | **에러 클리어 후 재시작 횟수 제한** | 짧은 시간 내 반복 트립 → 영구 래치 (전원 재인가 필요) |
| 0-7 | DRV8350 VDS/IDRIVE 설정 검증 | 저항값 → VDS 임계 → 차단 전류 계산, 필요 시 BOM 변경 |

### Phase 1 — 제어 구조 정비 🟠

| # | 항목 | 구체 내용 |
|---|------|-----------|
| 1-1 | **추종오차 제한 (가장 효과 큼)** | 주행 중에도 `|REF − pos| > e_max`이면 `REF = pos ± e_max`로 끌어당김 (REF_MUL도 같이). 또는 Iq* 포화 시 REF 적분 정지 (conditional integration). → 슬립·스톨 시 오차가 쌓이지 않음 → 따라잡기 충격 제거 |
| 1-2 | **속도 루프 도입** | `위치 P → 속도 PI → 전류 PI` 캐스케이드. AMR 휠은 속도 루프가 주(主), 위치는 오도메트리용으로 상위에서. 속도 PI 출력 포화 시 anti-windup |
| 1-3 | 속도 추정기 | 엔코더 차분 + 1차 LPF 또는 PLL 기반 관측기 (20kHz에서 계산, 지연 최소화) |
| 1-4 | 전류 PI anti-windup 스케일 수정 | `Esum += (Vsat − V)·1000/Ki` (또는 Kb = 1/Kp 표준식으로 재구성) |
| 1-5 | 전류 PI 게인 재산출 | R, L 실측 → `Kp = L·ωc, Ki = R·ωc` (단위 스케일 정리 포함) |
| 1-6 | 피드포워드 | 상위 가속도 명령 → `Iq_ff = J·α/Kt + 마찰`. 현재 dlc=8의 `NewInputCurrent_f`를 정식 FF로 사용 |
| 1-7 | REMOVE_CURRENT 기능 수정 또는 제거 | flag set 누락 수정 |

### Phase 2 — 강건성 / 슬립 대응 🟡

| # | 항목 | 구체 내용 |
|---|------|-----------|
| 2-1 | **DOB (부하토크 관측기)** | `T̂_L = Q(s)·[Kt·Iq − J_n·s·ω]` → 보상 + 모니터링 |
| 2-2 | **슬립 감지** | `T̂_L`이 갑자기 감소 + 바퀴 가속도가 명령보다 큼 → 슬립. 대응: 토크 한계를 낮추고 상위에 알림 (CAN 상태 비트 추가) |
| 2-3 | 스톨 감지 개선 | 속도≈0 & Iq ≥ 한계의 X% → 0.8초가 아니라 **I²t와 연계해 수백 ms 단위로** 토크 제한 → 정지 |
| 2-4 | 전기각 무결성 감시 | 주기적으로 MU150 절대각 vs QEI 누적 비교 → 차이 > 임계(예: 5°e) 시 재동기화 또는 에러 |
| 2-5 | 마찰 보상 | 쿨롱 + 점성 마찰 식별 후 FF |

### Phase 3 — HW 리비전 🔵

| # | 항목 |
|---|------|
| 3-1 | **Vbus 측정** (분압 + ADC) → OV/UV 보호, SVPWM 버스 전압 보상, 회생 토크 제한 |
| 3-2 | **버스 TVS / 브레이크 초퍼** (회생·서지 흡수) |
| 3-3 | nFAULT → MCPWM FLT 핀으로 라우팅 (HW 즉시 차단) |
| 3-4 | INA240 출력 → PIC32 내부 비교기(CMP) → PWM Fault (HW 과전류 차단, < 1µs) |
| 3-5 | 모터 NTC 연결 확정 및 FW 판독 |

### Phase 4 — 로봇 수준 🟣
- 좌우 바퀴 **결합 제어**: 한쪽 슬립 시 다른 쪽도 같이 토크를 제한해 방향 틀어짐을 방지 (상위 제어기와 협의)
- 적재량별 가감속 프로파일 (jerk 제한) — 슬립 자체를 줄이는 가장 저렴한 방법
- IMU 기반 실제 로봇 가속도와 바퀴 가속도 비교 → 정확한 슬립 감지

## 5. 원인 확정을 위한 시험 계획

| 시험 | 방법 | 확인할 것 |
|------|------|-----------|
| T1 바퀴 락 | 적재 상태에서 바퀴를 고정하고 속도 명령 유지 | 위치오차 증가율, Iq 포화 시간, 트립까지 시간, 코일 온도 상승률 |
| T2 슬립 재현 | 저마찰 판(아크릴 + 물) 위 급가속 | 오차 누적 → 그립 복귀 시 전류·속도 스파이크 |
| T3 회생 | 적재 + 최고속 → 급정지. 배터리 대신 **회생 흡수 불가 전원**(다이오드 직렬 PSU)로도 시험 | Vbus 피크 (차동 프로브), SHx 서지 |
| T4 커넥터 단선 | 주행 중 배터리 커넥터 순간 개방 (보호 장치 장착 후) | Vbus 피크 |
| T5 단락 | 저전압에서 상간 단락 | DRV8350 OCP 동작 여부, nFAULT 파형, FW 반응 |
| T6 전기각 드리프트 | 고부하 장시간 주행 후 QEI 누적 vs MU150 절대 | 카운트 유실 여부 |
| T7 소손품 분석 | 고장 보드/모터 분해 | FET 손상 형태(애벌런치 vs 열), 코일 변색 위치(특정 상?), 자석 접착부 상태 |

**FET 소손 형태로 원인 구분 팁:**
- 다이 중앙의 크레이터, 드레인-소스 단락 → **과전압/애벌런치** 의심 (시나리오 C)
- 패키지 전체 변색, 솔더 재용융 → **장시간 과열** (시나리오 A)
- 하이/로우 동일 레그가 함께 손상 → **동시도통/단락** (시나리오 D)
